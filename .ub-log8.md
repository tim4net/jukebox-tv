## Root cause (code + logs)
- (a) JukeboxRoomController.maybeResumeRoomSong skips the resume while mLoadingVideoId == roomVideoId && isLoadInFlight(). The marker is set by onNewVideo (any openVideo dispatch, e.g. a room "play"/resume dispatch) and only ever cleared by onVideoLoaded — which never fires when the player activity that should run the load was never started (cold launch on the join screen: no player view, no engine). With the timeout the only escape, a young marker silenced every join tick (roux2477: skip repeated 25s+; no "start PlaybackActivity" line exists in that window), keeping the app on the join screen.
- (b) jukebox_join.xml puts <requestFocus/> on the Browse YouTube button: it is the screen's only focusable view, so on the stuck join screen an OK press hit Browse and loaded a non-room video (.nina/roux2477.s4b.log 12:11:07/12:11:19 "start BrowseActivity (join screen browse button)" -> non-room video EjFN5iVKn6w).
